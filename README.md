# Calendar

Консольное Java-приложение, которое по номеру года строит и выводит
григорианский календарь на этот год.

Реализовано в рамках подготовки к собеседованию: задача — не просто
вывести календарь, а показать ООП-моделирование предметной области и
понимание того, что **уникальных календарей существует ровно 14**,
независимо от конкретного года.

## Ответ на теоретический вопрос

> Сколько всего уникальных календарей существует вне зависимости от
> номера года?

Раскладка календаря на год (то есть соответствие "число месяца ↔ день
недели") зависит только от двух параметров:

- дня недели, на который приходится 1 января (7 вариантов),
- високосный год или нет (2 варианта).

**7 × 2 = 14** уникальных календарей. Любой год попадает ровно в одну
из этих 14 комбинаций.

## Архитектура

Идея "14 уникальных календарей" не только упомянута в ответе на вопрос,
но и явно отражена в коде: приложение при старте строит все 14
вариантов заранее (eager-инициализация) и на каждый запрошенный год
лишь подбирает подходящий, а не пересчитывает всё заново.

```
com.ilyanin.calendar
├── Main.java                      — точка входа, сборка зависимостей, цикл ввода
├── model/                         — модели данных (не содержат логики)
│   ├── WeekDay.java                — день недели (enum)
│   ├── MonthName.java              — название месяца + базовое число дней (enum)
│   ├── CalendarKey.java            — ключ: (день недели 1 января, високосность)
│   ├── Day.java                    — число месяца + день недели
│   ├── Month.java                  — месяц: название + список дней
│   └── Calendar.java               — календарь: ключ + список из 12 месяцев
└── service/                       — логика
    ├── WeekDayCalculator.java      — вычисление дня недели (алгоритм Зеллера)
    ├── CalendarFactory.java        — строит один Calendar по CalendarKey
    ├── CalendarRegistry.java       — хранит все 14 календарей, отдаёт по году
    └── CalendarPrinter.java        — форматированный вывод в консоль
```

### Почему так разделено

Каждый класс отвечает на один вопрос (Single Responsibility):

| Класс                | Отвечает на вопрос                                  |
|-----------------------|------------------------------------------------------|
| `WeekDayCalculator`   | Как посчитать день недели по дате?                   |
| `Calendar` / `Month` / `Day` | Что такое календарь? (структура данных, без логики) |
| `CalendarFactory`     | Как построить один конкретный календарь по ключу?    |
| `CalendarRegistry`    | Где взять нужный календарь для заданного года?        |
| `CalendarPrinter`     | Как показать календарь пользователю?                  |

Такое разделение позволяет менять части независимо: например, если
понадобится другой формат вывода — меняется только `CalendarPrinter`,
остальной код не затрагивается. Если понадобится юлианский календарь —
добавляется новая реализация вычисления дня недели, без изменений в
моделях и в `CalendarRegistry`.

### `CalendarRegistry`: почему eager, а не lazy

Вычисление одного календаря — лёгкая операция (не поход в БД, не
сетевой запрос), поэтому выбор между "посчитать все 14 заранее" и
"считать по мере обращений" — не про производительность. Eager-подход
выбран осознанно, чтобы явно смоделировать факт "14 календарей
существуют независимо от того, какой год спросили" — то есть код
буквально отражает математический вывод, а не просто кэширует
результаты.

## Алгоритм Зеллера

День недели вычисляется без использования `java.time.LocalDate`, а
через классическую формулу (конгруэнцию) Зеллера — чтобы явно
продемонстрировать понимание алгоритма, а не делегировать вычисление
стандартной библиотеке.

Для месяца `m`, дня `d`, года `y`:

```
h = (d + ⌊13(m+1)/5⌋ + k + ⌊k/4⌋ + ⌊j/4⌋ + 5j) mod 7
```

где:
- `k` — год внутри века (`year % 100`);
- `j` — номер века (`year / 100`);
- `h` — результат: `0` = суббота, `1` = воскресенье, `2` = понедельник,
  ..., `6` = пятница.

Январь и февраль в формуле считаются 13-м и 14-м месяцами
**предыдущего** года (`m += 12; y -= 1`) — так добавленный день
високосного года (29 февраля) всегда оказывается в конце расчётного
года, и формуле не нужно отдельно проверять, наступил ли он уже.

Реализация — в `WeekDayCalculator.dayOfWeek(year, month, day)`.

## Запуск

### Через Maven

```bash
mvn compile exec:java -Dexec.mainClass=com.ilyanin.calendar.Main
```

или запустить `Main.java` напрямую из IDE.

### Тесты

```bash
mvn test
```

### Через Docker

```bash
docker compose run --rm calendar
```

Используется `run`, а не `up`: `run` создаёт разовый контейнер и
пробрасывает stdin/stdout в терминал, что необходимо для интерактивного
ввода года через `Scanner`. `up` для этого не подходит — он рассчитан
на долгоживущие сервисы и по умолчанию не даёт интерактивный доступ
к stdin.

Приложение работает в цикле: после вывода календаря на один год снова
предлагает ввести следующий год.
